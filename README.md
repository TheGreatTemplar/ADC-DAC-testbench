# ADC / DAC Testbench

Программа для отображения данных АЦП и управления испытательным стендом.
Версия 0.5 поддерживает рабочую **Perimetr_v.0.18.hex** и тестовую **testbench_1.hex**.
Перед подключением выберите установленную прошивку в поле «Формат».
Оба профиля предлагают 19200 бод, 8N1. Перезапустите программу после обновления.

## Рабочая прошивка v0.18

Выберите **«Рабочая v0.18»** (по умолчанию) и подключите COM-порт.
Программа читает версию, ступень усиления и запускает опрос сигнала / порога
командой 11 каждые 200 мс. График показывает обработанный знаковый сигнал
и тонкие линии ±действующего адаптивного порога в единицах алгоритма.
Порог возврата по UART не передаётся. Для него можно дополнительно включить
«Пороги через ST-Link / SWD»; профиль проверяет код v0.18 и использует её адреса ОЗУ.
Без ST-Link сигнал и порог срабатывания продолжают читаться по UART.

На вкладке «Протокол» блок **«Усиление · v0.18»** читает текущую ступень (1–8).
Нажмите одну из восьми кнопок **1–8**: отправляется команда 45, затем команда 15
проверяет фактическое значение. Активна одна кнопка. Во время опроса кнопки
не блокируются и не мигают; выбранная ступень отправляется после текущего ответа,
перед следующим опросом. При нескольких нажатиях ожидает последняя выбранная ступень.
Если подтверждение записи потеряно, приложение всё равно проверяет значение чтением,
без повторной записи. Значения показаны номерами ступеней, а не усилением в разах.
Тестовая прошивка эти UART-команды не обслуживает; управление в её профиле отключено.

Кнопки также позволяют читать версию (5), состояние (3), оценку фона (25).
В этом HEX команда 25 возвращает фон алгоритма, а не сырые коды АЦП.
v0.18 измеряет два канала АЦП и не передаёт поток A0–A2 или питание CH3.
Поэтому шкалы сырых АЦП, мВ CH2 и вольт батареи в рабочем профиле скрыты.
CSV: `source;time_s;processed_signal;trigger_threshold;device_state`.
Отдельная строка диагностики показывает обрыв кабеля (бит `0x04`) и КЗ (`0x20`)
красным, а также остальные флаги состояния. Она обновляется из каждого ответа 11
и из ручного запроса 3, даже при паузе графика. При отсутствии свежего состояния
более 2 с, ошибке чтения или отключении показания заменяются сообщением «нет данных».
В тестовом потоке A0–A2 байта состояния нет; диагноз по сырым кодам не выводится.
Тайм-аут или отказ прибора останавливает опрос; подробности находятся в журнале.
Проверено синтетическими ответами и loopback; обмен с прибором на v0.18 ещё нужно проверить.

## Прибор с прошивкой testbench_1.hex

Для считанного дампа STM32L151C6T6A используйте формат **«Тестовая · АЦП A0–A2»**
и **19200 бод, 8N1**. После подключения данные приходят
самостоятельно; опрос включать не нужно. Перезапустите программу после обновления исходников.

Прошивка передаёт строки `A0: 0123; A1: 0800; A2: 0FFF;` с окончанием CR.
Значения — четыре HEX-цифры. **CRC в этом потоке нет**. При приёме на 9600 байты
искажаются, и разбор ответов командного протокола к ним неприменим.
Назначение каналов подтверждено на приборе:

| Канал | Поле потока | Назначение |
| --- | --- | --- |
| CH1 | A0 | Контроль целостности КЧЭ |
| CH2 | A1 | Обработка тревоги |
| CH3 | A2 | Контроль питания (батареи) |

Статистика относится к CH1 / A0 (контроль целостности КЧЭ).
Справа от графика добавлена шкала CH2 в мВ при опоре 3,3 В:
`мВ = код × 3300 / 4095`. Слева остаётся «АЦП, код»; текущее значение CH2
показано одновременно в кодах и мВ. Шкала мВ скрывается при выключении CH2.
Для CH3 добавлена отдельная шкала напряжения питания в вольтах и текущий отсчёт.
Опора 3,3 В; после замены верхнего резистора делитель — 22 кОм от питания
до входа повторителя и 42,2 кОм от входа повторителя до PA8 (при измерении PA8=0):
`Uпит = код × 3,3 / 4095 × (22 + 42,2) / 42,2`.
Один код соответствует примерно 1,22598 мВ питания; арифметический полный масштаб
АЦП — 5,02038 В питания, но реальный диапазон ограничен также питанием повторителя.
Новые журналы сохраняют опору и номиналы делителя в полях `battery_vref_V`,
`battery_r_top_kohm`, `battery_r_bottom_kohm`. Старые записи до замены резистора
относятся к 10,2 / 42,2 кОм и требуют прежнего коэффициента пересчёта.
Галочка «Фильтр CH3» включена по умолчанию. Программа набирает 256 отсчётов
(примерно 4,5 с при текущем потоке), сортирует их, отбрасывает по 25 крайних
значений снизу и сверху и усредняет оставшиеся 206. До первого полного массива
показано «набор N/256»; дальше результат удерживается до окончания следующего массива.
Галочка переключает график, текущее напряжение и статистику CH3; CH1 и CH2 не меняются.
Фильтр работает и при паузе графика. Разрыв приёма более 2 с начинает новый массив,
чтобы отдельные измерения, например суточные, не смешивались. Это обработка
в программе стенда; расписание измерений и прошивка прибора не изменяются.

В CSV остаются исходные коды и добавлены `a2_trimmed256_code`, `battery_trimmed256_V`.
До накопления первого массива эти поля пустые; дальше в них хранится последняя
завершённая оценка. Оба варианта сохраняются независимо от состояния галочки.
Устойчивость оценки не означает подтверждённой абсолютной точности: фильтр
не исправляет ошибку опоры, коэффициента делителя или ограничение выхода ОУ.
CSV содержит `source`, `time_s`, `a0_kche_integrity_code`, `a1_alarm_processing_code`,
`a2_battery_supply_code` и два поля фильтра, описанные выше. Время задаётся приёмом ПК, а не часами АЦП.

Основание: в дампе `testbench_1.hex` по адресу `0x080028B6` загружается
`0x4B00` (19200) в поле BaudRate конфигурации USART1; WordLength, StopBits и Parity
равны нулю (8N1). По `0x08002970` находится строка формата
`A0: %04X; A1: %04X; A2: %04X;\r\n`. Цикл по `0x08002926` читает три
16-битных значения, форматирует строку и передаёт 30 байтов через USART1.
Сформированная строка занимает 31 байт, поэтому LF не передаётся. Реальный журнал
подтверждает приём строк с CR на скорости 19200. Парсер также поддерживает CR LF и LF.

### PA8 и время измерения питания в testbench_1.hex

При инициализации GPIO (`0x0800202A`) PA8 устанавливается в 0. Перед первым
запуском ADC DMA этот уровень повторно записывается по `0x080028FC`; вызов запуска —
`0x0800290A`. Между ними нет заданной задержки. В цикле повторных запусков
(`0x0800294E`) PA8 не переключается. На работающем приборе прочитаны
`GPIOA_MODER=0xA855000F` (PA8 — выход), `GPIOA_ODR=0x00000200` (PA8=0).
Активную полярность внешнего ключа нужно определять по схеме, а не по коду GPIO.

Регистры АЦП на приборе: `SQR5=0x820` — каналы 0, 1, 2 по порядку;
`SMPR3=0xDB` — выборка по 24 такта для каждого канала; `ADC_CCR=0x10000` —
HSI / 2, номинально 8 МГц. При 12 битах одно преобразование занимает
24 + 12 = 36 тактов, то есть 4,5 мкс. Выборка третьего канала начинается
примерно через 9 мкс от начала последовательности, результат готов примерно
через 13,5 мкс. Это расчёт времени АЦП, не измеренная задержка от фронта PA8:
между GPIO и началом последовательности выполняется код запуска HAL/DMA.
Время установления внешнего узла зависит также от его ёмкости; эквивалентное
сопротивление делителя после замены верхнего резистора — около 14,46 кОм.

### Адаптивные пороги через ST-Link / SWD

При подключении потока АЦП чтение порогов запускается автоматически. На вкладке
«Протокол» его можно отключить галочкой «Пороги через ST-Link / SWD». Нужны подключённый
ST-Link, его драйвер и установленная STM32 ST-LINK Utility (`ST-LINK_CLI.exe`).
Окно ST-LINK Utility и другие программы, занимающие программатор, должны быть закрыты.
В переносимую сборку эта внешняя утилита и драйвер не включаются.

Под графиком обновляются порог срабатывания, порог возврата, обработанный сигнал
и оценка фона. Это внутренние единицы алгоритма, а не мВ сырого A1.
В той же области графика есть отдельная правая шкала «Обработка / пороги, ед.».
Тонкие сплошные линии показывают ±порог срабатывания, пунктирные — ±порог возврата;
дополнительная кривая показывает обработанный сигнал, считанный через SWD.
Линии отражают последнее прочитанное значение порогов. Шкала не связана с кодами сырого АЦП.
Пороги действуют для обеих полярностей сигнала. Они читаются из ОЗУ по адресам
`0x2000034C` и `0x20000350` как float32. Расчёт расположен в функции
`0x08002BC4`, сравнения — в `0x08002558`. UART их не передаёт.

Чтение идёт отдельно от COM-порта примерно раз в секунду через SWD HOTPLUG,
без команд остановки, сброса, записи и программирования. Перед интерпретацией
ОЗУ проверяются SHA-256 двух участков прошивки testbench_1.hex (цикл измерений
и расчёт порогов). При несовпадении прошивки или ошибке SWD значения и линии скрываются,
а попытки чтения продолжаются автоматически.

### UART в Perimetr_v.0.18.hex

Статический анализ версии 0.18 подтвердил другой режим — командный протокол.
Обработчик по `0x080022BC` поддерживает команду 11 (`0x0B`, ветвь `0x080023F8`):
ответ содержит код команды, предыдущее обработанное значение (int16, little-endian),
текущий порог срабатывания (uint16, little-endian, дробная часть отбрасывается)
и байт состояния. Это чтение полей структуры `+0xC4`, `+0xBC`, `+0x13D`.
Команда 10 (`0x0A`, ветвь `0x080023E0`) возвращает порог только одним байтом;
для полноценного чтения предпочтительна 11. Порог возврата `+0xC0` в этих ответах отсутствует.

Запрос команды 11: `&0B0B\r` (байты `26 30 42 30 42 0D`). Контрольная сумма —
сумма бинарных CMD + DATA по модулю 256 (`0x080005E6`), передаётся двумя ASCII HEX.
Ответ — `!`, затем HEX-пары CMD, DATA и суммы, затем CR. В потоке testbench_1.hex
такого ответа нет. Прошивка 0.18 в прибор в ходе анализа не записывалась;
реальный UART-обмен с ней не проверялся. Приложение опрашивает команду 11 в профиле v0.18.

Документ `../Протокол обмена.doc` подтверждает номера команд в десятичном виде,
поля ответа 11 и диапазон усиления 1–8. В документе CRC указан одним сырым байтом,
но данный HEX реализует два ASCII HEX. Поэтому рабочий профиль фиксирует формат
по реализации прошивки; ручной профиль «Протокол 0.0» сохраняет выбор CRC.
Усиление: чтение 15 / 0x0F (`0x080024BE`), запись 45 / 0x2D (`0x080025DC`).
Запись сохраняет ступень в поле `+6` и переключает PA9–PA11 кодом «ступень − 1».
Пример установки ступени 8: `&2D0835\r`; подтверждение: `!2D2D\r`;
контрольное чтение: `&0F0F\r`, ответ для ступени 8: `!0F0817\r`.

## Запуск в Windows

Для USB-Flash используйте **переносимую сборку**, описанную ниже.
Следующие команды предназначены для запуска исходников на компьютере разработки.

Запустите `start.cmd` двойным щелчком. При первом запуске создаётся `.venv`
и загружаются зависимости (нужен интернет). Используется установленный Python 3.12+
либо локальный Python из среды Codex. При необходимости установку можно выполнить
отдельно командой `powershell -ExecutionPolicy Bypass -File .\setup.ps1`.

## Что доступно

- Один демонстрационный сигнал: 1000 отсчётов/с. В режиме потока прибора доступны
  три канала A0–A2; в демо и протоколе 0.0 используется только CH1.
- Список COM-портов обновляется каждые 1,5 секунды, выбранный порт сохраняется,
  пока он доступен. Подключать USB–COM можно после запуска программы.
  При раскрытом списке обновление откладывается до его закрытия. На время соединения
  порт и скорость фиксируются. Отключение адаптера обрабатывается как ошибка порта.
- В режиме «Протокол 0.0» CH1 показывает средневыпрямленный уровень
  команды 25; это не поток сырых АЦП. Пункты ниже о командах и CRC относятся к этому режиму.
- Выбор скорости COM-порта от 1200 до 1000000 бод, включая 921600.
  Поток A0–A2 — 19200; при выборе протокола 0.0 предлагается 9600.
  Формат — 8N1, без управления потоком.
  Доступность конкретной скорости зависит от адаптера; выбор не меняет прошивку.
- Включение каналов, окно 2–60 секунд, масштабирование мышью и автомасштаб по Y.
- Пауза графика: при запущенном демо приём в буфер продолжается.
- Текущее значение CH1, минимум, максимум, размах и СКО по отображаемому окну.
- Сохранение последних 60 секунд в CSV: источник `demo` / `device`, время, уровень
  CH1 в кодах и мВ (код × 0.6105) для протокола 0.0; A0–A2 в кодах для потока.
  Время прибора — время получения данных ПК.
- Приём и передача в отдельном потоке. Исходные RX/TX сохраняются в HEX-журнал
  `captures/exchange_*.jsonl` независимо от успешности разбора пакетов.
- Журнал TX/RX постоянно виден внизу главного окна. Его высоту можно менять
  перетаскиванием разделителя; свернуть полностью нельзя. Кнопка очистки удаляет
  только экранные строки, файл обмена сохраняется.
  После HEX-байтов показаны название команды, данные распознанного ответа и
  результат проверки CRC. Расшифровка RX собирается и при поступлении по частям.
- Демо каждые 200 мс добавляет пример запроса уровня и ответа с отметкой `[ДЕМО]`.
  Примеры учитывают DEC/HEX и выбранный CRC, не отправляются в порт и не попадают
  в файл реального обмена. Строки настоящего обмена отмечены `[ПРИБОР]`.
- Галочка «Номера команд в HEX»: снята — номер 25 означает код 0x19;
  установлена — 0x25. Для номеров 3 и 5 посылки одинаковы.
- CRC запросов выбирается: один сырой байт либо два ASCII HEX. Ответы проверяются
  в обоих вариантах. Рабочая гипотеза: сумма бинарных CMD + DATA по модулю 256,
  заголовок и CR в сумму не входят. Гипотеза требует проверки по реальным данным.
- Подключение не отправляет команд. Для непрерывного графика пользователь включает
  опрос уровня раз в 200 мс. Одновременно ожидается один ответ; тайм-аут 500 мс
  останавливает опрос. Документ задаёт 100 мс, запас выбран для первых испытаний.
- Изменение варианта протокола недоступно, пока ожидается ответ. Пакеты с неверной
  суммой и неизвестные команды сохраняются в журнал, но на график не попадают.
- Команды перезапуска и дистанционного контроля не реализованы.
  Запись усиления доступна только в профиле v0.18; остальные настройки не изменяются.

Значения демонстрационных сигналов — коды 12-битного АЦП. Они не являются
показаниями прибора. Время демо задаётся номерами отсчётов; это не измерение
реальной частоты дискретизации. После остановки демо остаются доступными просмотр
и сохранение буфера. ЦАП появится после согласования команд прибора.

## Разработка

Стек: Python, PySide2 (переносимая сборка) / PySide6 (разработка), PyQtGraph, NumPy, pySerial.
Отступы — 4 пробела. В языках с блочными скобками используется стиль Allman.

Снимок интерфейса без прибора: `.venv\Scripts\python.exe app.py --preview`.
Файл `preview.png` и локальное окружение исключены из Git.

## Переносимая сборка для USB-Flash

Запустите `powershell -ExecutionPolicy Bypass -File .\build-portable.ps1`.
Скрипт использует pip из окружения разработки, загружает Python 3.8.10 x86
и фиксированные зависимости из `requirements-portable.txt`, создаёт папку
`portable` и архив `ADC-DAC-testbench-portable.zip`. После изменения исходников
сборку нужно повторить. Существующая папка `portable` предназначена только для
результатов сборки; пользовательские записи храните отдельно.

Распакуйте архив целиком на флешку и запустите **START.cmd**. Устанавливать
Python или библиотеки на целевом компьютере не нужно. Интернет при запуске не нужен.
Локальное окружение `.venv` на флешку копировать не нужно.

Целевые ОС: Windows 7 **SP1**, Windows 8/8.1 и Windows 10, 32/64 бит.
Используется PySide2 / Qt 5.15.2 вместо Qt 6, который Windows 7 не поддерживает.
Фактический запуск на каждой старой ОС пока не проверен. Для Windows 7 нужны
системные обновления Universal CRT; для прибора — драйвер USB–COM адаптера.
Подробности находятся в `PORTABLE.txt`. ARM и Windows RT не входят в целевые ОС.
